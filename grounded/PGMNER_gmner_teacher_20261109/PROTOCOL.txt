Goal: Improve GMNER by addressing candidate recall/precision as well as grounding. Do not change manuscript or original PPIB/GOTA checkpoints.
Teacher: Existing Qwen2.5-VL-7B + exp_cot_paper/best adapter, selected by historical DEV epoch3. It is a separately supervised end-to-end GMNER model, not a new PGMNER result.
Cached teacher DEV/TEST rows must exactly match current official scaled multi-box gold annotations; gold fields are used for row alignment/scoring only and never passed into inference. Same 835-post test subset as previous run. Test has previously been examined and results remain exploratory.
Controls: PGMNER + context grounder (47.178 historical), independent teacher, PGMNER fixed entities with teacher boxes on exact mention/type agreement, consensus entity verification. Cache fusion thresholds .98/.995/.999 are selected on DEV only. A fusion identical to teacher is explicitly flagged and excluded from the final hybrid competition.
New GPU intervention: PGMNER entity candidates with confidence >=.9 are added as fallible hints to the teacher's complete GMNER prompt. Teacher may correct/delete/add candidates. Gold entities/types/regions/assistant messages are never included. Greedy generation, max512tokens, original system prompt and processor, no test-driven prompt changes.
Selection: Full DEV official GMNER F1 selects baseline, anchored grounding, consensus, candidate-assisted review, or nondegenerate cached fusion. Lock before new test generation. Teacher independent always reported separately. Test is not used to decide subsequent experiments automatically.
Report: Joint F1, MNER F1, counts, paired post bootstrap vs PG and teacher. An increase over PG does not establish PGMNER/PPIB/GOTA benefit over the teacher. Keep all DEV trials and negative outcomes.
Schedule: Cache audit/controls -> 3 GPU DEV shards -> DEV lock -> review TEST shards only if selected -> final results. Background process stops on errors and inference caches support clean restart.
